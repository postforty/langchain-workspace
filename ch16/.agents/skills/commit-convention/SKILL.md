# 커밋 컨벤션 스킬 (Commit Convention Skill)

이 스킬은 프로젝트에서 Git 커밋 메시지를 작성할 때 일관된 규칙(Conventional Commits)을 적용하도록 안내합니다.

## 언제 이 스킬을 사용하나요? (When to use this skill)

- 코드 변경 사항을 Git으로 커밋할 때
- 사용자에게 커밋 메시지를 제안하거나 생성할 때
- 리뷰나 수정 후 커밋 메시지를 다시 작성할 때

## 어떻게 사용하나요? (How to use it)

항상 다음 구조와 규칙을 준수하여 커밋 메시지를 작성하세요.

### 1. 커밋 메시지 구조
```text
<타입>: <제목>

<본문>

<꼬리말>
```

### 2. 타입 (Type)
변경 사항의 성격에 맞는 타입을 선택합니다.
- `feat`: 새로운 기능 추가
- `fix`: 버그 수정
- `docs`: 문서 수정
- `style`: 코드 포맷팅, 세미콜론 누락, 코드 변경이 없는 경우
- `refactor`: 코드 리팩토링
- `test`: 테스트 코드, 리팩토링 테스트 코드 추가
- `chore`: 빌드 업무 수정, 패키지 매니저 수정 (.gitignore, pyproject.toml 등)
- `ci`: CI/CD 설정 파일 및 스크립트 수정
- `perf`: 성능 개선을 위한 코드 수정

### 3. 작성 규칙
- **제목 (Subject)**: 50자를 넘지 않게 작성하며, 끝에 마침표(.)를 붙이지 않습니다. 한국어의 경우 주로 명사형으로 끝맺습니다.
- **본문 (Body)**: 선택 사항이나, 작성할 경우 한 줄에 72자를 넘지 않도록 줄바꿈을 합니다. "어떻게" 변경했는지보다 "무엇을", "왜" 변경했는지 설명합니다.
- **꼬리말 (Footer)**: 선택 사항이며, 관련된 이슈 트래커 ID 등을 참조할 때 사용합니다. (예: `Fixes #123`, `Resolves #45`)

### 4. 사용 예시
```text
feat: LangChain 클라이언트 초기화 로직 추가

Google GenAI를 사용하는 LangChain 클라이언트의 초기화 구성을 추가했습니다.
- RAG 파이프라인에서 사용할 임베딩 모델 설정
- API 키 유효성 검증 로직 포함

Resolves #12
```
